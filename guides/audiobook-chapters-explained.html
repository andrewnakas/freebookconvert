How Audiobook Chapters Work

A chapter is a timestamp with a name. The tricky part is that there are four places to store that list, and every player reads a different mix.

Published 2026-09-23 · All guides

The short answer

A chapter in an audiobook file is just a timestamp with a name: "Chapter 7, starts at 3:12:45". Players read the list and turn it into a chapter menu and skip buttons. The complications come from the fact that there are four different places that list can live, and each player reads a different subset of them.

Four ways audiobooks store chapters

1. One file per chapter

The oldest approach, and still the most common for MP3 audiobooks and CD rips: 01 - Opening Credits.mp3, 02 - Chapter 1.mp3, and so on. The "chapter list" is the folder listing. It works everywhere, but it depends entirely on the files sorting correctly, which is why the numbers are zero-padded (01, not 1; otherwise 10 sorts before 2). It also depends on the player remembering which file you were in.

2. MP4 chapter tracks (M4B, M4A)

MPEG-4 files can carry chapters in two formats. Apple's is a hidden text track: a second track in the file, alongside the audio, whose "samples" are the chapter titles, timed to start at each chapter. The other is a compact list stored in a chpl atom, popularized by Nero, a CD and DVD burning suite. Apple Books and most iOS apps read the text track. Many Android and desktop players read the Nero list. Writing both covers nearly everyone, which is what ffmpeg does by default and what the converters on this site produce.

3. ID3 chapter frames (MP3)

MP3's ID3v2 tagging has a chapter addendum that defines CHAP frames (each with a start time, end time, and title) and a CTOC frame that lists them in order. Podcast apps like Overcast and Pocket Casts support them well. Most music players ignore them completely. Handy for a single-file MP3 audiobook, but don't rely on them for a car stereo.

4. Sidecar files (.cue)

A .cue sheet is a small text file next to the audio that lists track start times. It comes from the CD-ripping world. A few players and audiobook servers read cue sheets, but for audiobooks it's the least portable option.

What happens when you convert

  • Folder of MP3s → M4B: each file becomes one chapter, named after the file. The chapter start is the running total of the previous files' durations. MP3 to M4B strips leading numbers from the names and lets you edit them before encoding.
  • M4B → MP3s: the reverse. The chapter table is read, and the audio is cut at each start time. M4B to MP3 names each file NN - Title.mp3 and tags it with a track number so any player sorts it correctly.
  • M4B → one MP3: the chapters can be carried over as ID3 chapter frames, so podcast apps still show them.

Why chapter marks sometimes drift

A chapter start is only as accurate as the durations it's computed from. MP3 files without a proper length header (a "Xing" or "Info" header) force software to estimate duration from the bitrate, and for variable-bitrate files that estimate can be off by seconds. Add up 60 such files and the last chapter can start noticeably early or late. Every MP3 encoder also pads a few milliseconds of silence at the start and end, so joined files accumulate tiny gaps. Most people never notice. If you do, re-exporting the source MP3s from any audio editor writes correct headers and fixes the drift.

Chapter names: where they come from

Commercial audiobooks carry real chapter titles ("The Boy Who Lived"). Many rips and self-made files only have "Chapter 1, Chapter 2". Converters can only preserve what's there. If names matter to you, fix them at the M4B stage. It's one file with one chapter list, and every player downstream will pick them up.

How long should a chapter be?

For listening, chapters are navigation, not structure. Anything from 5 to 45 minutes works well. Very long chapters (two hours of a single "Part One") make it hard to find your place after losing it. Very short ones, like one per page of a PDF, make the chapter list unusable. When you turn an ebook into an audiobook, the book's own chapters are usually the right size.

Common questions

My player shows no chapters in an M4B that definitely has them.

It probably reads only one of the two MP4 chapter formats, and the file only has the other. Re-muxing the file with ffmpeg (or running it through MP3 to M4B, then M4B to MP3 and back) writes both.

Can chapters overlap or have gaps?

The formats allow it, but players behave unpredictably. Well-formed files have each chapter end exactly where the next begins.

Do chapters change the audio?

No. Chapters are metadata. Adding, renaming, or removing them doesn't touch the audio data.
