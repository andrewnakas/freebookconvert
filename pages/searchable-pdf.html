Why make a PDF searchable?

  • Search. Ctrl-F on a 200-page document beats reading it.
  • Indexing. Google, your filesystem (Spotlight, Windows Search), and document-management systems index the text layer. A scan-only PDF is invisible to them.
  • Accessibility. Screen readers can speak the text. Without OCR, a scanned PDF is just a wall of images to assistive tech.
  • Copy-paste. Pull a quote into a document without retyping it.
  • Archival. If you're scanning paper for long-term storage, OCR makes the archive useful decades later.

How it works

  1. Render each page — pdf.js (Mozilla's PDF engine) draws every page to an off-screen canvas at the chosen resolution.
  2. Run OCR on the canvas — Tesseract.js reads each canvas and returns recognized words with their bounding boxes.
  3. Build a new PDF — pdf-lib creates a fresh PDF the same size as the source. The page image goes on first (JPEG-compressed), then each OCR'd word is drawn at its measured position with opacity 0. Invisible, but selectable.

Every step runs locally in your browser. The only network calls are for the libraries themselves (cached after first use).

Output size

We re-encode pages as JPEG at 80% quality. For a typical scanned book, the searchable output is about the same size as the input or a little smaller. The invisible text layer adds about 1-3 KB per page. If your input was a high-quality color archive, expect roughly 20-40% size reduction; if it was already heavily compressed, the output may grow a few percent.

Render scale tradeoff

  • 1.5x — fast, fine for high-quality scans (300+ DPI source).
  • 2x — recommended default. Balances speed and accuracy for most documents.
  • 3x — slow but best accuracy for low-resolution or faint scans.

Quality & limits

  • Selection regions are positioned per-word using Tesseract's bounding boxes. Selection is usable but not pixel-perfect. Highlighting "this exact sentence" works; trying to select half a word can be inconsistent.
  • The invisible text uses Helvetica's widths for positioning. Glyphs Helvetica doesn't have (rare in English) are silently skipped.
  • Two-column documents: OCR reads in visual order. Selecting across columns can pull the wrong words.
  • Handwriting won't OCR — printed text only.

Alternatives

If you only want the raw text and don't care about preserving the original look, use the scanned PDF to text page — it's faster and produces a smaller .txt file. If you have just a single image, use image to text.

FAQ

Will this work with PDFs that already have text?

Yes, but you'd be replacing the existing text with OCR text, which is almost certainly worse. If your PDF is already searchable, you don't need this tool.

Does the original PDF have to be visible (not encrypted)?

It has to be openable in your browser. Password-protected PDFs need to be decrypted first.

Can I do this on a phone?

Yes, but it's much slower — expect 20-40 seconds per page. For anything over 20 pages, a laptop is more practical.

Why does Cmd-F find some words but not their neighbors?

OCR isn't perfect. If a word is misrecognized, search won't find it. Increasing the render scale to 3x helps a lot for marginal scans.
